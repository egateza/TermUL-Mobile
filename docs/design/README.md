Sistem desain TermUL Mobile: klien SSH pribadi untuk ponsel (Android dan iOS), turunan TermUL desktop. Gelap, padat informasi, dan berhati-hati terhadap hal yang berisiko. Setiap nilai di bawah memakai nama token; jangan menulis heks, ukuran atau radius langsung.

## Fondasi konten

- Tulis dalam Bahasa Indonesia. Istilah teknis baku tetap berbahasa Inggris: host, terminal, sudo, SFTP, vault, scrollback, snippet.
- Gunakan huruf besar hanya di awal kalimat. Label tombol tanpa titik, tanpa tanda seru, tanpa emoji.
- Jelaskan akibat, bukan prosedur: "Teks masuk ke prompt tanpa menekan Enter, jadi belum dijalankan." Sebut angka dan nama nyata: "Tempel 3 baris?", "Sisa 2 ketukan lagi untuk menyalakan api."
- Setiap status memakai kata, bukan hanya warna: "online", "offline", "menyambung ulang", "berisiko", "Hari ini selesai". `ok` dan `bad` nyaris sama terang, jadi kata atau ikon yang membedakan keduanya.
- String teknis (host, user@ip, path, perintah, angka streak) selalu bergaya mono (`terminal`, `terminal-sm`, `key`, `count-*`). Judul dan penjelasan memakai `h1`, `h2`, `title`, `body`, `body-sm`, `caption`.
- Tindakan yang bisa merugikan (menempel banyak baris, perintah `rm -rf`, host key berubah) selalu menampilkan isi dan konsekuensinya sebelum tombol konfirmasi, dan pilihan aman menjadi tombol utama.

## Fondasi visual

- Hanya ada tema Gelap. Susun lapisan dari `ground` (halaman) ke `surface` (kartu, sheet, bar) ke `surface-raised` (kontrol di atas kartu). Terminal dan editor memakai `ground-deep`.
- `accent` adalah satu-satunya warna aksi: tombol utama, pilihan aktif, ikon aktif, cincin fokus. Teks di atas isian `accent` memakai `on-accent`, bukan putih. Jangan menambah warna aksi kedua.
- `ok`, `bad`, `ice` hanya untuk status dan selalu disertai kata atau ikon. `level-1` sampai `level-9` hanya untuk api streak; jangan dipakai sebagai warna dekorasi.
- Pisahkan permukaan dengan tepi 1px `line`, bukan bayangan; sistem ini tidak punya bayangan. `line` hanya 1,47:1 terhadap `ground`, jadi tepi kontrol yang membawa makna (input, sakelar mati, titik progres kosong) memakai `line-strong`.
- Fokus papan ketik: 2px solid `accent`, offset 2px, pada semua elemen interaktif.
- Setiap target sentuh minimal `tap-min` (44px). Tombol utama di dasar layar `button-lg`, baris pengaturan `row-min`, baris host `row-comfy`.
- Radius: kartu dan baris host `radius-xl`; input dan baris pengaturan `radius-lg`; tombol-khusus `radius-md`; sheet dan widget `radius-3xl`; chip dan tombol bulat panjang `radius-pill`; titik dan tombol api `radius-round`.
- Jarak: margin tepi layar `space-8`, gutter daftar `space-5`, padding kartu `space-6` sampai `space-7`, jarak antar elemen sebaris `space-3`, antar tombol-khusus `space-2`.
- Bingkai desain ponsel `screen-w` x `screen-h`. Layar utama: header, area gulir, lalu bar navigasi bawah empat tab (Host, Sesi, Snippet, Pengaturan; tab SFTP dihapus 2026-10-17, lihat butir SFTP). Layar terminal tidak memakai bar navigasi agar ruang terminal maksimal. Panel dan dialog naik dari bawah sebagai `BottomSheet`.
- Keadaan: terpilih atau menekan = isian `accent` dengan teks `on-accent`; nonaktif = opasitas 0,4; meredup menunggu = `ink-faint`.
- Gerak hanya terjadi sebagai respons peristiwa dan mematuhi reduce motion. Lihat bagian Gerak.

## Ikonografi

- Ikon adalah SVG garis inline: viewBox 24, tebal garis 1,75, ujung dan sambungan bulat, warna `currentColor`. Pakai komponen `Icon` dan namanya; jangan menggambar ulang.
- Jangan memakai emoji. Glyph teks hanya untuk tombol-khusus di `KeyButton` (panah, backspace, enter).
- Ikon mandiri wajib punya label aksesibilitas; ikon yang menyertai teks disembunyikan dari pembaca layar.
- Api streak digambar oleh `Flame`, bukan ikon biasa, karena bentuknya berganti menurut state.

## Komponen

- Aksi: `Button` untuk teks, `IconButton` untuk ikon saja. Satu `Button` varian `primary` per layar atau sheet; dalam dialog berisiko, tombol utama adalah pilihan aman.
- Input: `TextField` (pencarian dan form), `Switch` (baris pengaturan dengan deskripsi), `Segmented` (2-4 pilihan eksklusif), `Stepper` (satu angka dalam rentang kecil, dengan tombol kurangi dan tambah), `Chip` (filter, tag, level).
- Umpan balik: `Banner` (peringatan, risiko, es), `Toast` (konfirmasi sesaat, maksimal satu baris), `StatusDot` (titik dengan kata), `Progress` (bar atau titik ketukan).
- Permukaan: `Card`, `BottomSheet`, `HostRow`, `NavBar`.
- Terminal: `KeyButton` untuk baris tombol-khusus dan panel tombol, `TerminalSurface` untuk menampilkan baris terminal berwarna.
- Streak: `Flame` dan `StreakChip`. Aturan state ada di bagian Streak api.

## Spike teknis

Sebelum UI penuh dibangun, tumpukan Flutter (`dartssh2`, `xterm`) diuji ke server nyata. Daftar uji, kriteria lulus, hasil, dan keputusan desain ada di `spike.md`. Catatan teknis lengkap (masalah, penyebab, perbaikan, dan kode yang terbukti jalan) ada di `spike-temuan.md`. Hasil spike hanya mencakup Android; iOS belum diuji. Rancangan menjaga koneksi di latar belakang (foreground service, izin, dan pengaturannya) ada di `android.md`.

## Batasan yang berlaku

- Hanya tema Gelap dan orientasi potret yang didefinisikan. **Aplikasi dikunci ke potret (keputusan pemilik, 2026-10-17)**, supaya tampilan konsisten; contoh landscape di kanvas (terminal 2f, 2g, 2m, 2n, layar utama 1b, form host 1c) adalah tambahan implementasi yang tidak dipakai lagi, dibiarkan sebagai rujukan bila landscape diaktifkan kembali. Kodenya di aplikasi juga dibiarkan; mengaktifkannya lagi cukup mengganti daftar orientasi di `main.dart` dan `android:screenOrientation` di manifest.
- Sembilan tier api, ambang harinya dan palet warnanya mengambil nilai dari artifact desktop "Streak Api TermUL"; jika `StreakTier` di kode desktop berbeda, kode itulah yang benar.
- Tepi `line` pada input dan chip di prototipe tidak mencapai 3:1; sistem ini mencatatnya dan menyediakan `line-strong`.

## Catatan dari implementasi Flutter (diperbarui 2026-10-17)

Keputusan yang muncul saat aplikasi dibangun dan menyimpang atau menambah dari desain di atas. Rinciannya di `docs/implementation-plan.md` repo aplikasi.

- Platform: Android saja; iOS belum diuji sama sekali (kalimat awal "Android dan iOS" tidak lagi berlaku).
- Pengaturan: layar Pengaturan sudah ada dengan bagian Terminal (pratinjau, `Stepper` ukuran font dan tinggi baris, bentuk gagang seleksi, saklar "Konfirmasi tempel satu baris" di bawah kartu, tombol "Kembalikan bawaan") dan bagian Koneksi (saklar "Sambung ulang otomatis", bawaan nyala: mati berarti sambungan yang putus menunggu tombol "Sambung sekarang"; saklar "Pertahankan koneksi di latar belakang", status izin notifikasi, tombol ke pengaturan baterai; lihat `android.md` dan prototipe `Settings` 6b). Layar ini adalah tab Pengaturan di `NavBar` lima tab (sebagai tab, tanpa tombol kembali). Bagian lain di prototipe (Tema, Keamanan, Data, Streak, Widget) belum dibuat.
- Terminal: tinggi baris bawaan aplikasi 1,3, bukan 1,5 dari token `terminal` (di HP 1,5 hanya memuat sekitar 12 baris di landscape sehingga daftar proses `htop` tidak terlihat); token `terminal` tetap rujukan untuk teks terminal di luar pengaturan. Ukuran font 8 sampai 24 px (bawaan 13), tinggi baris 1,0 sampai 2,0. Tanpa cubit-untuk-zoom; ukuran hanya diubah lewat Pengaturan.
- Warna ANSI magenta dan sian tidak ada di `tokens.json`; aplikasi memakai `#D59BF6` dan `#7FD6E0` (versi cerah `#E6BDFB` dan `#A9E8EF`) supaya `htop`, `vim`, dan `ls --color` terbaca di `ground-deep`.
- Keluar dari terminal (tombol kembali di layar maupun sistem) meminta konfirmasi selama shell hidup, karena shell di server ikut berakhir.
- Sambung ulang (diperbarui 2026-10-16): otomatis, dengan jeda bertingkat 2, 5, 10, lalu 30 detik (tetap di 30). Sebelum menyambung, host diperiksa dulu; selama belum terjangkau (mis. mode pesawat) banner `warn` "Menunggu server terjangkau…" menampilkan hitungan mundur ("Mencoba lagi dalam N detik.") dengan tombol "Sambung sekarang" (digambar di prototipe 2k). Rahasia dibaca dari vault saat sambungan pertama (satu prompt biometrik) lalu dipegang di memori selama sesi hidup dan layar menyala, jadi putus dan sambung ulang di tengah pemakaian tidak meminta prompt lagi. Layar mati (dianggap tidak dipakai) melepas rahasia: sambung ulang berikutnya meminta prompt sekali, begitu aplikasi terlihat lagi. Bila prompt dibatalkan atau gagal, sambung ulang otomatis berhenti dan banner `warn` "Perlu verifikasi" ("Menyambung ulang membutuhkan sidik jari, PIN, atau pola perangkat.") menampilkan tombol "Tampilkan prompt" (prototipe 2l); prompt tidak muncul lagi sampai tombol itu ditekan. Dua sesi tidak membuka prompt bersamaan, dan setelah satu prompt dibatalkan sesi lain tidak membuka prompt sendiri dalam 30 detik. Percobaan otomatis hanya berjalan selagi aplikasi terlihat; login ditolak, kunci rusak, atau host key ditolak menghentikannya dan menunggu pengguna.
- Penguncian rahasia tiga tingkat (mengubah K15 di `spike.md`): biometrik; PIN, pola, atau sandi perangkat bila HP tanpa biometrik; tanpa kunci layar boleh menyimpan tetapi dengan peringatan. Rahasia selalu terenkripsi di Keystore.
- Tombol cepat terminal: Fn (F1 sampai F12) ditaruh setelah Alt; mode ringkas landscape memakai tombol status 32 dp dan tombol cepat 36 dp.
- Tempel di terminal (diperbarui 2026-10-16): tombol **Tempel** ada di baris tombol cepat, setelah Fn. Papan klip kosong: toast "Papan klip kosong". **Satu baris pendek (sampai 40 karakter, tanpa baris baru, tanpa tanda bahaya)** menampilkan **popover** berisi teks yang akan ditempel, keterangan "Masuk ke prompt, belum dijalankan", dan tombol Tempel (prototipe `TerminalPasteMenu`, contoh 2b); ketukan di mana saja di luar popover (terminal, bar atas, tombol cepat) menutupnya. Popover dipusatkan pada titik asalnya (baris kursor bila dari tombol Tempel, jari bila dari tekan-tahan) dan dibatasi 8 dp dari tepi layar, di atas titik itu (di bawahnya bila tidak muat). Selain tombol Tempel, popover bisa dipicu dengan **tekan-tahan di area kosong** terminal (sisa baris di kanan teks, baris kosong, atau ruang di bawah prompt); tekan lama di atas teks tetap memilih kata. Pemicu ini juga aktif di layar alternatif dan mouse mode (`tmux`, `vim`, `htop`) selama yang ditekan sel kosong. Prototipe memicunya lewat ketukan di kursor. Saklar "Konfirmasi tempel satu baris" (Pengaturan, Terminal; bawaan nyala) mematikan popover itu: satu baris pendek yang aman langsung masuk ke prompt. **Teks lebih panjang dari 40 karakter, banyak baris, berisiko, atau memuat karakter kontrol selalu lewat dialog**, apa pun pengaturannya. Dialog "Tempel N baris?" menampilkan isi (maksimal 50 baris, sisanya diringkas), baris berisiko diberi kata "berisiko", dan akibatnya. Pilihan aman (Batal) menjadi tombol utama bila ada baris berisiko atau server belum mendukung tempel aman; tempel banyak baris biasa dengan tempel aman aktif memakai Tempel sebagai tombol utama. Ambang 40 karakter adalah nilai awal untuk dicoba di HP. Di layar pendek (landscape, tinggi kurang dari 480 dp) popover bersusunan **mendatar**: teks dan keterangan di kiri, tombol Tempel di kanan, tinggi sekitar 56 dp (bukan sekitar 100 dp) karena dengan keyboard terbuka area terminal hanya sekitar 130 dp; letaknya selalu di dalam area aman (di bawah bilah status, di atas keyboard) dan turun ke bawah jari bila di atasnya tidak muat (contoh 2m).
- Varian tanpa tempel aman (digambar di prototipe 2h): bila program di server tidak menyalakan tempel aman (bracketed paste; bash di bawah 5.1), banyak baris langsung dijalankan, jadi dialog memberi peringatan "Server ini belum mendukung tempel aman: setiap baris langsung dijalankan begitu ditempel." menggantikan kalimat "belum dijalankan", dan toast hanya "Ditempel · N baris". Karakter kontrol (mis. ESC) dibuang dari teks dan dilaporkan; teks lebih dari 100.000 karakter ditolak. Pola baris berisiko sama dengan prototipe.
- Seleksi dan salin teks (diperbarui 2026-10-16): mengikuti prototipe `Terminal` (bilah dengan jumlah karakter, Batal, Salin, Semua; toast "Disalin · N karakter"). Gagang berbeda atas pilihan pemilik: prototipe memakai bulatan `info` bertangkai, bentuk gagang bisa dipilih di Pengaturan, bagian Terminal, lewat `Segmented` "Bentuk gagang seleksi" (tambahan; digambar di prototipe `Settings`): **Tetesan** (bawaan; bulatan 16 dp dengan ujung runcing di atas yang sisinya sedikit melengkung, ujungnya menunjuk batas seleksi), **Segitiga** (bulatan dengan segitiga terpisah di atasnya, alas segitiga melengkung mengikuti bulatan), dan **Bulatan** (polos). Semuanya `accent` bertepi `ground` 3 dp, bukan bulatan `info` bertangkai seperti prototipe `Terminal` (prototipe itu tidak diubah). Ujung tetesan dan segitiga tidak statis: bila badan gagang dijauhkan dari tepi layar, ujungnya miring ke titik seleksi yang sebenarnya (gagang berputar utuh tanpa memanjang; sudut paling miring 45 derajat); di baris paling bawah gagang dibalik, ujungnya menyentuh sisi atas sel dan badannya di atas. Bulatan tidak punya ujung sehingga tidak miring. Tambahan di luar prototipe: kaca pembesar di atas jari saat menyeret gagang (120 x 56 dp, perbesaran 1,6x, tepi `accent`; di tepi layar wilayah yang diambil digeser ke dalam dan garis `accent` menandai titik yang ditunjuk; contoh 2i), serta gagang yang dijepit di dalam layar dan minimal 36 dp dari tepi kiri dan kanan supaya tidak jatuh di zona gestur kembali Android.
- Seleksi: belum bisa diterapkan, desain tetap. (1) Petunjuk bilah di desain "Ketuk kata lain untuk memperluas pilihan" mengandaikan ketukan memperluas pilihan; xterm 4.0.0 menghapus seleksi saat terminal diketuk, jadi aplikasi sementara menulis "Seret gagang untuk mengubah pilihan". (2) Warna: desain memakai latar `terminal-selection` dengan teks `terminal-selection-ink`, tetapi xterm 4.0.0 menggambar seleksi di atas teks tanpa menggambar ulang teksnya, sehingga latar pekat menutupi huruf; aplikasi sementara memakai `#3E7CA8` dengan alpha 55%. Warna sementara ini diterima pemilik (2026-10-16), jadi xterm tidak ditambal; token `terminal-selection` dan `terminal-selection-ink` tidak berlaku untuk terminal sungguhan. (3) Belum dibuat: Cari, Kirim ke host lain, Simpan sebagai snippet, Bagikan, dan Salin sebagai satu baris.
- Sesi di latar belakang (tambahan, 2026-10-16): menekan kembali di terminal membuka sheet "Keluar dari terminal?" dengan tiga pilihan, **Tetap terhubung di latar belakang** (tombol utama), **Putuskan** (`danger`), dan **Batal**; digambar di prototipe 2j. Bila pengaturan "Pertahankan koneksi di latar belakang" mati, ada catatan `warn` bahwa Android bisa memutus sambungan dan tombol "Buka Pengaturan". Sesi yang dibiarkan hidup muncul di layar **Sesi aktif** (prototipe 12): satu kartu per sesi dengan nama host (beberapa sesi ke profil yang sama dibedakan " · sesi N"), `user@host:port` dan jam mulai, status dengan kata (Tersambung, menyambung ulang, Terputus, perlu tindakan), tombol Putuskan per sesi (dengan konfirmasi), dan Putuskan semua bila lebih dari satu. Mengetuk kartu membuka lagi terminal yang sama dengan riwayat layar utuh. Sesi yang putus saat di latar belakang tidak disambung ulang otomatis (alur sambung bisa memunculkan prompt biometrik); ia disambung ulang saat dibuka lagi.
- Gulir otomatis seleksi (tambahan, tanpa perubahan visual): saat gagang diseret, jari dalam 56 dp dari tepi atas atau bawah area terminal menggulir isi ke scrollback (makin dekat tepi makin cepat, sampai 900 dp per detik) dan seleksi ikut memanjang; berhenti saat jari menjauh dari tepi atau dilepas.
- `NavBar` (diperbarui 2026-10-16): bar lima tab sudah dibangun sesuai desain: Host, Sesi (lencana jumlah sesi di latar belakang), SFTP, Snippet, Pengaturan. Tab dibangun saat pertama dibuka lalu dipertahankan (pencarian Host tidak hilang); tombol kembali dari tab lain menuju Host dulu; bar disembunyikan saat keyboard sistem terbuka; layar terminal dan form tidak memakainya. Ikon sesi dan pengaturan di header daftar host dihapus karena pindah ke bar. Tab Sesi di prototipe `Terminal` (beberapa sesi dalam satu layar terminal) belum dibuat; di aplikasi satu layar terminal menampilkan satu sesi.
- Snippet (tambahan sementara): fiturnya belum ada, jadi tab-nya membuka layar sederhana berisi judul dan banner `info` "Belum tersedia" dengan satu kalimat keterangan (prototipe 13; tab SFTP di prototipe itu tidak dipakai lagi karena SFTP sudah dibangun, lihat butir SFTP). Desain layar Snippet yang sebenarnya (prototipe 7) tetap berlaku.
- SFTP (tambahan, 2026-10-17; irisan pertama: menjelajah): tab SFTP tidak lagi layar sementara. Ia membuka **layar pilih sumber** (contoh 4b): judul `h1`, satu kalimat pengantar, bagian **Sesi terbuka** (hanya bila ada sesi terminal di latar belakang; mengetuknya memakai sambungan sesi itu tanpa login lagi) dan bagian **Koneksi sendiri** (semua host; koneksi SFTP dibuka sendiri dengan vault, biometrik, dan verifikasi host key yang sama dengan terminal), keduanya baris 56 dp dengan ikon, nama, `user@host:port` bergaya mono, dan panah. Setelah tersambung layar jelajah mengikuti prototipe 4: tombol kembali, judul "SFTP" dengan subjudul "nama · terhubung" (hijau, `ok`), breadcrumb yang bisa diketuk, baris `..`, folder (ikon `info`) di atas berkas, ukuran dan waktu ubah dalam format Indonesia ("1,2 KB · 2 jam lalu"), tarik untuk memuat ulang, dan tombol muat ulang di header. Memilih berkas menampilkan bar bawah "nama dipilih" dengan satu tombol **Salin path** (toast "Path disalin"). Pilihan dilepas begitu **Unduh** atau **Salin path** ditekan (bar pilihan hilang), jadi Unduh tidak bisa ditekan berulang untuk berkas yang sama; unduhan yang berjalan terlihat di panel transfer. Sambungan putus (mis. soket ditutup Android di latar belakang): subjudul menjadi "nama · terputus" berwarna `bad` dan banner `warn` "Sambungan SFTP terputus" dengan tombol **Sambung ulang** (contoh 4e). **Sambung ulang otomatis memakai mekanisme yang sama dengan terminal** untuk koneksi sendiri: sebelum menyambung host diperiksa, selama belum terjangkau banner "Menunggu server terjangkau…" menghitung mundur ("Mencoba lagi dalam N detik.", jeda 2, 5, 10, lalu 30 detik) dengan tombol "Sambung sekarang" (contoh 4f); sedang menyambung: "Menyambung ulang…" ("Folder yang dibuka tetap terlihat."); prompt dibatalkan: "Perlu verifikasi" dengan tombol "Tampilkan prompt" (contoh 4g). Rahasia dipegang di memori selama layar menyala (tanpa prompt baru); layar mati melepasnya; saklar "Sambung ulang otomatis" berlaku; daftar lama tetap terlihat dan folder yang sama dibuka lagi setelah tersambung. Untuk sesi yang dipinjam, banner menyatakan sesi terminalnya terputus dan SFTP tersambung lagi begitu sesinya tersambung ulang (sesi itu yang menyambung ulang). Transfer yang berjalan dibatalkan saat sambungan putus. Server tanpa subsistem SFTP: banner `risk` "SFTP tidak tersedia di server ini". **Keluar selalu meminta konfirmasi** (dari folder awal; di dalam folder yang dibuka dari folder lain, tombol kembali di header maupun sistem lebih dulu kembali ke folder yang dikunjungi sebelumnya, satu tingkat per ketukan, dan melompat lewat breadcrumb kembali ke asal lompatan): sheet "Keluar dari SFTP?" dengan Batal dan Keluar (contoh 4c). Bila ada transfer berjalan, sheet berjudul "Transfer masih berjalan", memuat jumlah dan daftar transfer dengan persen, catatan bahwa berkas unggahan yang belum lengkap dihapus dari server dan berkas unduhan dari perangkat, Batal menjadi tombol utama, dan "Batalkan transfer dan keluar" (`danger`) membatalkan semuanya (contoh 4d; varian ini baru teruji otomatis karena unduh dan unggah belum dibuat). Menutup layar menutup koneksi SFTP sendiri; sesi terminal yang dipinjam tetap hidup. Belum bisa sesuai desain layar 4, desain tetap: tombol Edit di bar pilihan dan editor berkas jarak jauh (dijadwalkan di irisan berikutnya). **SFTP dari terminal (2026-10-17):** tombol folder "Buka panel SFTP" di header terminal (prototipe 2, 44 dp, di kanan) membuka penjelajah SFTP lewat **sambungan sesi terminal yang sama**: tanpa login ulang dan tanpa sesi baru. Tombol kembali di SFTP menuju terminal yang sama **tanpa sheet konfirmasi**; konfirmasi ("Transfer masih berjalan") baru muncul bila ada transfer, karena transfer ikut dibatalkan. Menutup SFTP hanya menutup kanalnya, sesi terminal tetap hidup. Bila terminal terputus lalu tersambung ulang, kanal SFTP dibuka lagi. **Unduh dan unggah (tambahan, 2026-10-17):** header mendapat tombol **Unggah berkas** (ikon unggah, di kiri muat ulang) yang membuka pemilih berkas sistem; bar pilihan berisi **Unduh** (tombol utama) dan **Salin path** berdampingan (contoh 4h; bar layar 4 yang memuat Edit tetap rujukan untuk Edit). Unduhan disimpan ke **Unduhan/TermUL** di perangkat (nama kembar diberi akhiran " (1)") dan toast menyebut tempatnya ("Diunduh ke Unduhan/TermUL · nama"). Selama transfer berjalan, **panel transfer** muncul di atas bar pilihan: satu baris per transfer dengan nama, persen (`accent`), bilah kemajuan 4 dp, dan tombol batal 44 dp (contoh 4h); persen hanya tampil bila ukurannya diketahui.
